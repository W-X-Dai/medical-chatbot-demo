# ELVINA pre-consultation demo

Interactive demonstration of the ELVINA pre-consultation web interface
(frontend 0.19.2), published at
https://w-x-dai.github.io/medical-chatbot-demo/.

It runs entirely in the browser: no server, language model or patient data is
involved, and every patient is synthetic. It lets readers of the paper try the
interfaces directly; the source code and the paper describe the full system.

## What you can try

A progress bar at the top guides you through three steps:

1. **Check-in**: the registration slip of a synthetic patient carries a QR code
   with a one-time code (scanning it with a phone opens this site and redeems
   it). Next to it is the patient's TW Core FHIR record (Patient, Encounter,
   Condition, MedicationRequest, Observation) and the questionnaire fields it
   fills in. Press 「掃描 QR code」 to start, as a patient would by scanning it.
2. **AI pre-consultation**: the interview starts with the prefill the system
   derived from that record in the paper's E2 run (including its model-based
   mapping of chronic conditions), so basic data and known history are not asked
   again. Answer by clicking: questions with options keep them; the chief
   complaint offers two examples, one of which triggers the red-flag rules and
   stops the interview. The questionnaires, question
   order, answer validation, body pain map and red-flag rules are the ones used
   in the paper, and the AI doctor plays pre-rendered clips (CosyVoice3 speech,
   MuseTalk lip-sync) for every question.
3. **Clinician view**: when the interview is submitted, the doctor workspace
   opens the consultation you just completed.

Also available from the clinician view:

- **Doctor workspace** (`#/doctor`): 30 example consultations that are actual
  outputs of the paper's end-to-end experiment (E2), including the AI-drafted
  record, differential and test suggestions and MedGemma background knowledge.
  An interview you finish in the same tab is added to the list. The four
  suggested knowledge questions show answers generated by the system's
  doctor-chat pipeline, here with the local MedGemma 27B as the chat model;
  they are unedited model output, not literature citations.
- **Rules Center** (`#/doctor/rules`): the chief-complaint safety rules.

## Differences from the full system

The interface is the real one; only the data source differs.

- In the full system a language model also normalises the chief complaint for
  the structured safety rules and chooses the questionnaire when no keyword
  matches; here an unmatched complaint continues with the shared questions.
- Your own interview's AI summary stays "being generated", other knowledge
  questions, speech recognition, FHIR write-back and SNOMED CT search show the
  system's own "service unavailable" messages, and re-analysis shows the stored
  analysis of the case.
- State is kept in memory and resets when the page is reloaded.

## Contents

- `index.html`, `launch.html`, `assets/` — the built application (`npm run build:demo`)
- `avatar-clips/` — 54 pre-rendered AI doctor clips plus `manifest.json`
- `dr training pc.png` — the AI-generated doctor image used by the avatar
- `script_review.html` — standalone offline form for clinicians to review the 30
  synthetic validation scenarios; answers stay in the reviewer's browser until
  exported as JSON (no network requests)

The avatar and its voice are synthetic and do not represent a real clinician.
The system is not a medical device and its output is not a diagnosis.
